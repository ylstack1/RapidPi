Rapid Pi 1.1.0 is Pi [1.5.0](https://github.com/earendil-works/pi/releases/tag/v1.5.0), built ahead of time as before. What
Pi 1.5.0 brings is in its release notes; in short: changelogs for updated extension packages, faster streaming of large tool
calls and code-heavy answers, `PI_SELF_UPDATE_COMMAND` / `selfUpdateCommand`, and GPT-6.1 Terra. Everything Rapid Pi adds is
[1.0.9](1.0.9.md)'s.

Rapid Pi's versions now go 1.0.9, 1.1.0: the last number runs from 0 to 9, then the middle one goes up.

### Changed

- **Pi 1.5.0** ([#237](https://github.com/opensec-git/Rapid Pi/pull/237), [#229](https://github.com/opensec-git/Rapid Pi/issues/229)):
  Rapid Pi's changes are kept on top of it. **For extensions:** Pi 1.5.0 validates tool arguments with
  `@earendil-works/pi-schema` instead of TypeBox, so TypeBox features outside JSON Schema (`Type.Refine()`, `Type.BigInt()`,
  `Type.Undefined()`, codecs, `Format.Set()` formats) no longer apply to tool arguments, and plain JSON Schema tools (MCP
  tools too) get the same coercion as TypeBox ones.
- **`rapid-pi compile`** gives compiled-in extensions the same `@earendil-works/pi-ai` as Pi 1.5.0's loader: pi-ai's compat
  entry plus TypeBox's `Type` and `StringEnum`. Run `rapid-pi compile` again after updating.
- **Startup profile**: recorded again for Pi 1.5.0, on Linux, macOS and Windows.

### Fixed

- **Numbers in tool arguments**: a number that does not fit (`1e400`) or `NaN` fails validation again, as with Pi 1.4.0, instead
  of reaching the tool as `Infinity`.
- **Provider stream wrappers** ([#226](https://github.com/opensec-git/Rapid Pi/issues/226),
  [#227](https://github.com/opensec-git/Rapid Pi/pull/227) by [@Patrick-Kappen](https://github.com/Patrick-Kappen)): a
  provider extension that returns the API's stream wrapped in a Proxy that changes the events (to map renamed tool names
  back, say) had the wrapper skipped. Such a stream is now iterated through the wrapper.
- **Dependencies** ([#231](https://github.com/opensec-git/Rapid Pi/issues/231),
  [#232](https://github.com/opensec-git/Rapid Pi/issues/232)): with Pi 1.5.0's dependencies `npm audit` finds nothing (zod
  4.6.7, undici 8.12.3), and `shx` is gone, with the old minimatch under `glob` 7.

With the default settings Rapid Pi sends what Pi 1.5.0 sends. The release archives on the Apple M5, 1.0.9 / **1.1.0**
(medians of 25 runs, 15 for the -jit build; a second copy of 1.0.9 varied as much):

|---|---|---|---|
| `pi --version` | 54 / **54** M | 4.4 / **4.4** ms | 19.2 / **19.0** MB |
| `pi -p` (5 model turns) | 203 / **204** M | 18.1 / **17.8** ms | 52.7 / **51.7** MB |
| Interactive, 5 prompts | 605 / **601** M | 86 / **87** ms | 64.1 / **62.6** MB |
| -jit build, `pi -p` | 208 / **209** M | 18.9 / **18.9** ms | 53.4 / **52.5** MB |

Ready to type: 28 / **28** ms.

Pi is 1.5.0. The engine and runtimes are 1.0.9's: Bun 1.4.3 with Bun 1.4.4's TLS fix (oven-sh/bun#46300), which
`rapid-pi doctor` now names on its engine line ([#228](https://github.com/opensec-git/Rapid Pi/issues/228)).

### Install

```bash
curl -fsSL https://rapid-pi.opensec.in/install.sh | sh
```

```powershell
irm https://rapid-pi.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://rapid-pi.opensec.in/install.ps1 | iex"
```

or `rapid-pi update`, or `npm install -g --allow-scripts=rapid-pi rapid-pi`, or `bun add -g --trust rapid-pi`, or:

- Homebrew (macOS on Apple silicon, Linux): `brew install opensec-git/tap/rapid-pi`
- Scoop (Windows): `scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket`, then `scoop install opensec-git/rapid-pi`
- mise: `github:opensec-git/Rapid Pi` with the options in the [installation guide](https://rapid-pi.opensec.in/docs/installation.html)

The installer checks the release signature with OpenSSL 3, `ssh-keygen` (OpenSSH 8.1 or later), or an installed Rapid Pi.
Every archive also has a GitHub build attestation: `gh attestation verify <file> -R opensec-git/Rapid Pi`.
