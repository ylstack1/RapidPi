Rapid Pi 1.0.9 is a fix release: after `/new`, the screens of the old session no longer stay in memory, and the engine takes
the root certificates and blocked keys of Bun 1.4.4. Everything else is [1.0.8](1.0.8.md).

### Fixed

- **Memory after `/new`** ([#220](https://github.com/opensec-git/Rapid Pi/pull/220) by
  [@Shrub24](https://github.com/Shrub24)): a component drawn inside several parents kept every parent it was ever drawn in,
  with their children and rendered lines, for as long as it lived. Across several `/new` in a long session that held old
  message trees (800 MB in one session). Parents are now held weakly and freed once Pi drops them; live parents still
  redraw when the component changes.

### Changed

- **TLS** ([#222](https://github.com/opensec-git/Rapid Pi/pull/222)): the bundled root certificates are those of NSS 3.131.1
  (118, against 121), and a certificate chain that holds a public key on Node's blocked list fails with `CERT_REVOKED`, as
  in Bun 1.4.4 and Node 22.23.4, 24.22.1 and 26.12.1. This applies to `fetch` (HTTP/3 included), `node:tls`, `node:https`
  and WebSocket.
- **minimatch 11.0.1** ([#221](https://github.com/opensec-git/Rapid Pi/pull/221)): package resource filters and model
  patterns match as before (5,724 patterns and paths compared with 10.2.6).

With the default settings Pi draws the same screens and sends the same requests as 1.0.8. The release archives on the
Apple M5, 1.0.8 / **1.0.9** (medians of 25 runs, 15 for the -jit build; a second copy of 1.0.8 varied as much):

| | Instructions | CPU | Peak memory |
|---|---|---|---|
| `pi --version` | 54 / **54** M | 4.5 / **4.5** ms | 19 / **19** MB |
| `pi -p` (5 model turns) | 203 / **203** M | 18.8 / **18.8** ms | 53 / **53** MB |
| Interactive, 5 prompts | 607 / **609** M | 91 / **91** ms | 64 / **64** MB |
| -jit build, `pi -p` | 209 / **209** M | 19.3 / **19.3** ms | 53 / **53** MB |

Ready to type: 30 / **29** ms.

Pi is 1.4.0. The runtimes are new: Bun's patch adds #222.

### Install

```bash
curl -fsSL https://rapid-pi.opensec.in/install.sh | sh
```

```powershell
irm https://rapid-pi.opensec.in/install.ps1 | iex
```

```bat
powershell -c "irm https://rapid-pi.opensec.in/install.ps1 | iex"
```

or `rapid-pi update`, or `npm install -g --allow-scripts=rapid-pi rapid-pi`, or `bun add -g --trust rapid-pi`, or:

- Homebrew (macOS on Apple silicon, Linux): `brew install opensec-git/tap/rapid-pi`
- Scoop (Windows): `scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket`, then `scoop install opensec-git/rapid-pi`
- mise: `github:opensec-git/Rapid Pi` with the options in the [installation guide](https://rapid-pi.opensec.in/docs/installation.html)

The installer checks the release signature with OpenSSL 3, `ssh-keygen` (OpenSSH 8.1 or later), or an installed Rapid Pi.
Every archive also has a GitHub build attestation: `gh attestation verify <file> -R opensec-git/Rapid Pi`.
