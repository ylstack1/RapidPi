Get started

Installation

Install Rapid Pi with one command. The installer downloads the release for your system, checks its checksum and signature, and puts rapid-pi on your PATH. It does not change your Pi installation.

Requirements

  • Linux on x86-64 or ARM64 with glibc 2.17 or later (Raspberry Pi 3 and later, AWS Graviton and Ampere included). musl distributions such as Alpine are not supported.
  • macOS 13 or later on Apple silicon. There is no build for Intel Macs.
  • Windows 10 (1809) or later, or Windows 11, on x64. Windows on ARM64 runs the x64 build, in Windows 11's x64 emulation.
  • Android 7 or later on 64-bit ARM, in Termux. See Android (Termux).

Rapid Pi does not need Node.js, Bun or Pi. npm is only needed if you install with npm.

Install

$ curl -fsSL https://rapid-pi.opensec.in/install.sh | sh
$ curl -fsSL https://rapid-pi.opensec.in/install.sh | sh
irm https://rapid-pi.opensec.in/install.ps1 | iex
powershell -c "irm https://rapid-pi.opensec.in/install.ps1 | iex"

On an older Windows 10 whose PowerShell only offers TLS 1.0, run these two lines in PowerShell instead:

[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor 3072
irm https://rapid-pi.opensec.in/install.ps1 | iex
$ npm install -g --allow-scripts=rapid-pi rapid-pi

--allow-scripts=rapid-pi lets npm run the package's install script, which puts the Windows executable in place. On macOS and Linux, the first run of rapid-pi downloads the release that matches the package's version.

$ brew install opensec-git/tap/rapid-pi

On macOS on Apple silicon and on Linux (x86-64 with AVX2, and ARM64). The formula installs the default build of the latest release, checked against its SHA256SUMS, and links rapid-pi into Homebrew's bin. For the JIT build or the x86-64 build for CPUs without AVX2, use the installer.

scoop bucket add opensec-git https://github.com/opensec-git/scoop-bucket
scoop install opensec-git/rapid-pi

On Windows x64. The manifest in opensec-git/scoop-bucket installs the default build of the latest release, checked against the checksum in its SHA256SUMS, and puts rapid-pi on your PATH with a Scoop shim. For the JIT build, use the installer.

[tools."github:ylstack1/RapidPi"]
version = "latest"
version_prefix = "bolt-v"
asset_pattern = 'rapid-pi-{{ os(macos="darwin", windows="win32") }}-{{ arch() }}.tar.gz'
platforms.windows-x64 = { asset_pattern = "rapid-pi-win32-x64.zip" }
platforms.macos-arm64 = { rename_exe = { pi = "rapid-pi" }, filter_bins = "rapid-pi" }
platforms.linux-x64 = { rename_exe = { pi = "rapid-pi" }, filter_bins = "rapid-pi" }
platforms.linux-arm64 = { rename_exe = { pi = "rapid-pi" }, filter_bins = "rapid-pi" }
$ mise install

On macOS on Apple silicon, Linux (x86-64 with AVX2, and ARM64) and Windows x64, with mise's github backend. It installs the default build of the latest release, checked against the digest GitHub reports for it, renames the launcher pi to rapid-pi, and puts only rapid-pi on your PATH. For the JIT build, use the installer.

The installer:

  1. Downloads the release for your platform and CPU, from the npm registry's CDN with GitHub as a fallback.
  2. Checks it against the release's SHA256SUMS, and checks the Ed25519 signature of SHA256SUMS against Rapid Pi's release key. A download that does not verify is not installed. (On macOS and Linux, the signature check needs OpenSSL 3 or an earlier Rapid Pi; without either, the installer checks the checksums only and says so.)
  3. Installs it to ~/.rapid-pi and links rapid-pi into ~/.local/bin. On Windows, it installs to %USERPROFILE%\.rapid-pi and asks before adding it to your PATH. It needs no administrator rights.
  4. Offers three optional extensions by OpenSec (subagents, a todo list and fast file search), and installs them only if you say yes. See OpenSec extensions.

Then run rapid-pi in a project. Continue with the Quickstart.

Android (Termux)

In Termux from F-Droid or GitHub (the Google Play version has no glibc packages), run the same command as on Linux:

$ curl -fsSL https://rapid-pi.opensec.in/install.sh | sh

Rapid Pi is a glibc program and Android's libc is not glibc, so the installer first installs Termux's glibc (pkg install glibc-repo && pkg install glibc, after asking), sets it as the executable's loader, and links rapid-pi into $PREFIX/bin. rapid-pi is a small launcher that starts Rapid Pi in Android's time zone and without Termux's LD_PRELOAD, which glibc cannot load; the programs Rapid Pi starts get it back. The installer also copies Termux's resolv.conf and hosts to $PREFIX/glibc/etc, where Termux's glibc reads them.

rapid-pi: command not found? ~/.local/bin is not on your PATH. Add export PATH="$HOME/.local/bin:$PATH" to your shell profile and open a new terminal.

Builds

Each platform has a default build and a JIT build. The installer picks the default build for your CPU. To choose another, set RAPIDPI_VARIANT. See Choose a build for when the JIT build is the better choice.

$ curl -fsSL https://rapid-pi.opensec.in/install.sh | RAPIDPI_VARIANT=arm64-jit sh
$ curl -fsSL https://rapid-pi.opensec.in/install.sh | RAPIDPI_VARIANT=x64-jit sh     # x86-64
$ curl -fsSL https://rapid-pi.opensec.in/install.sh | RAPIDPI_VARIANT=arm64-jit sh   # ARM64 and Termux
$env:RAPIDPI_VARIANT = "x64-jit"

# ~/.zshrc or ~/.bashrc; use x64-jit on Linux x86-64
export RAPIDPI_VARIANT=arm64-jit

On macOS and Linux, the npm package reads RAPIDPI_VARIANT every time it runs, so keep it set in your shell profile. If it is unset later, the next run switches back to the default build.

On Windows, the npm package picks the build when it is installed or updated. Set the variable first, then install:

$env:RAPIDPI_VARIANT = "x64-jit"
npm install -g --allow-scripts=rapid-pi rapid-pi

To change builds later, set or clear RAPIDPI_VARIANT and run the install again.

rapid-pi update keeps the build you chose.

Verify the installation

$ rapid-pi --version
1.4.0 (Rapid Pi 1.0.0, darwin-arm64, JIT off)

The first number is the Pi release this build is made from. The rest is the Rapid Pi release, the platform, and whether the JIT is on. To check that Pi runs its compiled code, see Check the compiled code.

Update

$ rapid-pi update                  # Rapid Pi only
$ rapid-pi update --all            # Rapid Pi and your extensions
$ rapid-pi update --rollback       # back to the build the last update replaced
$ rapid-pi update --channel beta   # take pre-releases too (stable: the latest release only)

An update keeps the build it replaces; rapid-pi update --rollback puts it back without downloading anything, and running it again goes forward again. The channel is kept for the installation. With npm, run npm update -g rapid-pi; the next run downloads the new release. With Homebrew, run brew upgrade rapid-pi; rapid-pi update says so and changes nothing, and --rollback is not available. With Scoop, run scoop update rapid-pi, and scoop reset rapid-pi@<version> to go back to a version Scoop still keeps. With mise, run mise upgrade --bump github:ylstack1/RapidPi, and mise use -g github:ylstack1/RapidPi@<version> for another version. rapid-pi update and --rollback give these commands for a Rapid Pi that Scoop or mise installed, and change nothing. Running the installer again also updates.

Uninstall

Run the installer again and choose uninstall. It removes the Rapid Pi builds from ~/.rapid-pi, the one kept for a rollback among them, and the rapid-pi link. With npm, run npm uninstall -g rapid-pi, then delete ~/.rapid-pi/npm, where the npm package keeps the release it downloaded. With Homebrew, run brew uninstall rapid-pi; with Scoop, scoop uninstall rapid-pi; with mise, mise unuse -g github:ylstack1/RapidPi.

Your Pi configuration in ~/.pi/agent belongs to Pi and is not removed.

Manual download

Download a build from the latest release, check it against SHA256SUMS, unpack it, and run ./pi (on Windows, rapid-pi.exe). Keep the unpacked folder together: the executable uses the files around it for themes, HTML export and image tools. Link to the executable rather than copying it.

DownloadFor
rapid-pi-linux-x64.tar.xzLinux, CPUs with AVX2
rapid-pi-linux-x64-baseline.tar.xzLinux, any x86-64 CPU
rapid-pi-linux-arm64.tar.xzLinux ARM64, any 64-bit ARM CPU (in Termux, use the installer)
rapid-pi-darwin-arm64.tar.xzmacOS on Apple silicon
rapid-pi-win32-x64.zipWindows x64

The JIT builds are rapid-pi-linux-x64-jit.tar.xz, rapid-pi-linux-arm64-jit.tar.xz, rapid-pi-darwin-arm64-jit.tar.xz and rapid-pi-win32-x64-jit.zip. To check a download:

$ sha256sum -c --ignore-missing SHA256SUMS
macOS: downloaded with a browser A browser marks downloads as quarantined, and macOS then refuses Rapid Pi's ad-hoc signed executable (zsh: killed, or "cannot verify the developer"). Install with the installer or npm, which do not quarantine, or remove the attribute from the unpacked folder: xattr -dr com.apple.quarantine rapid-pi-darwin-arm64.

Installer options

Set these in the environment of the installer: curl ... | NAME=value sh on macOS and Linux, $env:NAME = "value" before the command on Windows.

VariableEffect
RAPIDPI_VARIANTThe build to install (see Builds).
RAPIDPI_VERSIONA release tag such as bolt-v1.0.0. Default: the latest release.
RAPIDPI_CHANNELstable (the latest release; the default) or beta (the newest release, pre-releases included), for this installation and its updates.
RAPIDPI_INSTALLWhere to install. Default: ~/.rapid-pi (Windows: %USERPROFILE%\.rapid-pi).
RAPIDPI_BIN_DIRmacOS and Linux: where to link rapid-pi. Default: ~/.local/bin.
RAPIDPI_NO_PATH=1Windows: do not add Rapid Pi to your PATH.
RAPIDPI_YES=1Do not ask: take the default action, install no extensions, and do not offer to start Rapid Pi.
RAPIDPI_EXTENSIONSyes or no: whether to install OpenSec's optional extensions without asking.
RAPIDPI_SOURCEWhere to download the executable from: auto (npm, then GitHub; the default), npm or github. Checksums and signatures always come from the GitHub release.
RAPIDPI_NPM_REGISTRYAn npm registry or mirror. Default: https://registry.npmjs.org.
RAPIDPI_CONNECTIONSmacOS and Linux: connections to download over at once. Default: 4.
